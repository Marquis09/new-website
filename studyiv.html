Project H: Community Hub Redesign

From text-heavy archives to a bento grid interface

Real Redesign proposal and working prototype for Hartshill Bible Church, Stoke-on-Trent · Church content sanitized

Executive Summary

  • Situation: The church’s agency-built website was text-dense and hard to scan, especially on phones and for older visitors.
  • Task: Modernise the interface without changing the site structure the church was used to.
  • Action: Kept the legacy layout and replaced the walls of text with a modular bento grid of scannable tiles and larger touch targets, then built it as a responsive prototype.
  • Result: Presented to church leadership, who preferred the proposed design to the agency’s version. The prototype is live to view.
  • Status: A prototype and proposal. Formal usability testing and an accessibility audit have not yet been carried out.

Project Details

  • My Role: UX Designer UI Designer Front-end Developer
  • Tools & Tech: HTML5 CSS3 UX Strategy
  • Project Type: Redesign proposal with a working responsive prototype, presented to the church’s leadership.
  • Constraints: Keep the legacy layout structure · Sanitized client content · Usable by older visitors and on mobile
Process Index: 1. Vision | 2. Bento UI | 3. Decisions | 4. Before/After | 5. Prototype | 6. Feedback | 7. Next Steps | 8. Reflection
📁 1. The Vision: Same Layout, Better Interface

I set out to show that information architecture doesn’t have to feel overwhelming. I kept the structural layout the church was used to, but overhauled the visual interface. By breaking up the “wall of text”, I aimed for a site that is action-oriented and easier for all ages to use.

The church’s existing site had been produced by an external agency. I did not have access to the original files, so the redesign works from the public layout and sanitized content rather than the agency’s source.

📁 2. UI Approach: The Bento Grid

The defining change was a bento-box interface, inspired by the Lumia style. This modular approach let me keep the same site structure while changing how the information is presented:

  • Modular tiles: Information is broken into scannable, bite-sized blocks instead of long passages.
  • Larger touch targets: Buttons and links are sized for comfortable tapping on mobile, with older visitors in mind.
  • Less on screen at once: Detail moves into tiles and secondary views, so each screen carries less copy and a clearer hierarchy.

📁 3. Key Decisions & Alternatives

The brief had one firm constraint: the site structure had to stay recognisable. That meant the design work happened in how content was presented, not where it lived.

Decision Alternative considered Why I chose this
Keep the legacy layout structure Restructure the whole site The church was used to the existing structure. Changing the interface without moving things around lowered the risk of confusing regular visitors.
Bento grid of tiles Shorter paragraphs in the same long-page format Tiles make each topic a single, scannable unit and give a clear place for a button or link, which long paragraphs do not.
Larger touch targets Keep the original small links Many visitors are older and many will use phones, so larger targets make navigation easier and reduce mis-taps.
Build a working prototype Present static mock-ups only A live, responsive prototype lets leadership try the design on their own phones rather than imagine it.

📁 6. Feedback & Evidence

I presented the redesign to the church’s leadership at a final presentation. The feedback below is their reaction, not the result of a formal usability study, and I have kept the two clearly separate.

Completed

  • Review of the legacy site against the church’s needs
  • Working responsive prototype
  • Final presentation to church leadership

Not yet done

  • Before/after word count of the main pages
  • Usability testing, including with older visitors
  • Accessibility audit (WCAG 2.1 AA)
  • Analytics on how visitors use the tiles

Leadership feedback (summarised from the final presentation):

Leadership said that cutting back the text-heavy sections made the core message more impactful and the site faster to navigate, and preferred the proposed design to the agency’s version.

On text reduction: the redesign visibly shows less copy at once, but I have not yet measured it. A before-and-after word count of the main pages is on my next-steps list so any figure I quote can be checked.

📁 7. Next Steps & Future Iterations
  • Measure the change: Count the words on the main pages before and after, so the reduction in text can be stated with a verified number.
  • Usability testing: Run short tests with a few visitors, including older users, to check the larger touch targets and tile layout work in practice.
  • Accessibility audit (WCAG 2.1 AA): Test colour contrast and keyboard and screen-reader use, including a high-contrast option for low-vision visitors.
  • Content management: Build bento tile templates in a headless CMS so non-technical staff can add news tiles themselves.
  • Analytics: Track clicks on individual tiles to refine which items sit where in the grid.
📁 8. Technical & Ethical Reflection

What this project demonstrates:

  • Redesigning an interface within a firm constraint (keep the existing structure).
  • Turning a dense, text-heavy page into a modular layout with a clearer hierarchy.
  • Designing for older visitors and mobile use from the start.
  • Presenting a prototype to stakeholders and responding to their reaction.

Limitations:

  • The positive reaction came from leadership, not from a wider group of visitors or formal testing.
  • Claims about easier use for older visitors are design intentions that I still need to test.
  • The prototype uses sanitized content, so it does not show how real church content behaves in the grid.

To respect the privacy of the organisation, identifying content has been sanitized. This project shows my ability to take an agency-managed “wall of text” and turn it into a modern modular interface that meets visitor needs and the leadership’s goals.
